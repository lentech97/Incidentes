Gestión de incidentes

Clasificación, priorización y trazabilidad

Cada evento se valida, prioriza y registra según impacto, criticidad y tiempo de respuesta. Esto permite actuar con rapidez, mantener evidencia y reducir tiempos de resolución sin perder contexto operativo.

Arquitectura del proyecto

Frontend y backend: responsabilidades separadas

La interfaz estática se sirve desde Express y se comunica con la API REST mediante solicitudes Fetch.

01

Cliente · public/

Frontend

HTML5 · CSS · JavaScript · Fetch API

  • Presenta el panel, los formularios y la sesión del usuario.
  • Consulta, registra, edita y filtra incidentes desde la API.
  • Muestra detalles, métricas, errores y controles según el rol.
  • Mantiene el token JWT solo en memoria del navegador.

Archivos principales: index.html, css/styles.css y js/app.js.

02

Servidor · src/

Backend

Node.js · Express · API REST · SQLite

  • Expone endpoints de autenticación y gestión de incidentes.
  • Valida datos y aplica autenticación JWT y permisos por rol.
  • Guarda usuarios e incidentes en SQLite con migraciones.
  • Centraliza seguridad, registro de solicitudes y respuestas de error.

Capas: routes/, controllers/, services/, models/ y middleware/.

Navegador → Fetch + JWT → API Express → SQLite
